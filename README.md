# isomux-loop

The Isomux app for the continuous loop (design: isomux `internal-docs/continuous-loop-design.md`, task 178dbb5a).

- Pause stops dispatch and the tick (Isomux PM pauses around restarts and while batch work holds workers).
- Dispatch, every 2 minutes: each free Isomux Worker among Workers 1..N (N set on the status page, 1 to 6, default 2) gets the next ready board task (priority, then age), claimed with a versioned PATCH, and a `/isomux-loop-worker <task id>` message.
- Tick, hourly: idle workers that hold a task get a nudge; Isomux Main hears how many tasks wait to merge.
- Curator wake, every 10 minutes, also while paused: open P0-P3 tasks in the room with no tag and no card in the app go to the curator (P4 backlog gets a card only when the curator proposes to promote it; a proposal keeping a P4 task at P4 is refused) in one message (a task is announced again only after an hour). Every board read the app makes (status, the Triage list, packets, the Backlog, the wake; one read is shared for 20 s) withdraws the undecided cards and packets whose task is done, obsolete or gone, so a closed task leaves Triage within 20 s.
- Triage, Nil's only queue for loop work: the curator's proposals (priority, class auto/design/hold ("on hold": the loop never touches it), keep, with an optional new title and scope, or obsolete; Nil's note can change anything) and the workers' design packets (a question, 2-4 options with their cost and one recommended, a folded markdown body, screenshots, branch and diff links), packets first. Nil's decisions go to the curator in one message per burst; the curator writes them to the board and reports back.
- Each task id has a button that copies it.
- Split view: on a screen at least 900 px wide, "Diagram beside" shows the task-state diagram next to Triage; it updates after each decision and every 15 s while the page shows it, and a draggable divider sets the widths. The browser keeps both choices.
- Backlog: the tasks of the Backlog state (P4, no card), oldest first. "Bring in" gives one a priority (P0-P3) and a class; that is a decided card that goes to the curator like any other.
- Sign-off before the push: a worker posts the copy and visible changes of a task at hand-off; Isomux Main reports every merge (and every revert) with its commit. Merged items show with a word diff per copy entry and their screenshots; screenshots posted as a before/after pair (`?pair=<name>&side=before|after`) show side by side like Old/New. Nil can comment on each copy entry and screenshot (a note, or the exact new text in quotes; saved as he types). He approves (with comments, Approve also files a P0 `[auto | ready] Copy edits: <title>` task with them; the merged commit still goes out with the next push and the edits follow as their own commit and sign-off item), or rejects with a note that carries his comments (the app asks Main for the revert at once). "Approve and push" sends Main the push go for the last main sha Main reported, once every item is decided and every rejection reverted. Every reported merge waits in the Push state until Main reports the push of a sha that includes it (`POST /api/signoff/pushed`). The app cannot tell which member pressed a button: the office passes it no member identity.
- Status: the task states as a diagram with live counts, including Triage (exactly the open cards of the Triage tab, whatever the board says of their tasks) Sign-off (merged, its sign-off item waits for Nil or for its revert) and Push (merged, not pushed yet) (tap a state to list its tasks; done and obsolete list the last 20 by close time), the sign-off count, the ready queue, holders, merging, on hold. Close times come from each task's history, cached by task version in `closed-times.json`.

The board is the loop's only state. The app keeps triage proposals, packets, sign-off items, images and the settings in `$ISOMUX_APP_DATA_DIR`. It reaches the board and other agents with the app token, which has its owner's reach since isomux task c0204eb6. Constants (room, worker names, intervals) are in `src/config.ts`.

API: `curl -s http://127.0.0.1:$PORT/api/help`. Run: `bun run start`. Tests: `bun test`.
