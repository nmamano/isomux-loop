# isomux-loop

The Isomux app for the continuous loop (design: isomux `internal-docs/continuous-loop-design.md`, task 178dbb5a).

- Pause stops dispatch and the tick (Isomux PM pauses around restarts and while batch work holds workers).
- Dispatch, every 2 minutes: each free Isomux Worker among Workers 1..N (N set on the status page, 1 to 6, default 2) gets the next ready board task (priority, then age), claimed with a versioned PATCH, and a `/isomux-loop-worker <task id>` message.
- Tick, hourly: idle workers that hold a task get a nudge; Isomux Main hears how many tasks wait to merge.
- Curator wake, every 10 minutes, also while paused: open tasks in the room with no tag and no card in the app go to the curator in one message (a task is announced again only after an hour); the same run withdraws undecided triage cards whose task closed meanwhile.
- Triage, Nil's only queue for loop work: the curator's proposals (priority, class auto/decide/authority, keep/rescope/obsolete) and the workers' design packets (a question, 2-4 options with their cost and one recommended, a folded markdown body, screenshots, branch and diff links), packets first. Nil's decisions go to the curator in one message per burst; the curator writes them to the board and reports back.
- Sign-off before the push: a worker posts the copy and visible changes of a task at hand-off; Isomux Main reports every merge (and every revert) with its commit. Merged items show with a word diff per copy entry and their screenshots; screenshots posted as a before/after pair (`?pair=<name>&side=before|after`) show side by side like Old/New. Nil can comment on each copy entry and screenshot (a note, or the exact new text in quotes; saved as he types). He approves (with comments, Approve also files a P0 `[auto | ready] Copy edits: <title>` task with them; the merged commit still goes out with the next push and the edits follow as their own commit and sign-off item), or rejects with a note that carries his comments (the app asks Main for the revert at once). "Approve and push" sends Main the push go for the last main sha Main reported, once every item is decided and every rejection reverted. The app cannot tell which member pressed a button: the office passes it no member identity.
- Status: the task states as a diagram with live counts, including "Needs your sign-off" (merged, its sign-off item waits, has edits requested or waits for its revert) (tap a state to list its tasks; done and obsolete list the last 20 by close time), the sign-off count, the ready queue, holders, tasks waiting to merge, never picked. Close times come from each task's history, cached by task version in `closed-times.json`.

The board is the loop's only state. The app keeps triage proposals, packets, sign-off items, images and the settings in `$ISOMUX_APP_DATA_DIR`. It reaches the board and other agents with the app token, which has its owner's reach since isomux task c0204eb6. Constants (room, worker names, intervals) are in `src/config.ts`.

API: `curl -s http://127.0.0.1:$PORT/api/help`. Run: `bun run start`. Tests: `bun test`.
